# 《奥术王座》UI / UX 改进建议

> 基于 `src/FantasyCardBattle.tsx` 当前实现（2026-06-12）的评审。
> 按优先级分为三档：🔴 高（影响核心体验）、🟡 中（明显可感知的提升）、🟢 低（锦上添花）。

---

## 一、信息可见性（玩家"看不到该看的东西"）

### 🔴 1. 敌方随从无法查看详情（已修改）
点击敌方随从目前没有任何反馈（除非处于攻击/施法选目标状态）。玩家看不到敌方随从的**名称、描述、是否嘲讽/冲锋的文字说明**，只能靠 emoji 和两个数字猜。
- **建议**：点击（或长按/悬停）任意随从时，复用现有的"选中卡牌大图预览"面板（`FantasyCardBattle.tsx:666-680`）展示该随从的完整信息。

### 🔴 2. 手牌中的法术牌不显示效果（已修改）
手牌上法术牌只显示一个"法术"二字（`HandCard`，约 578 行），玩家必须先点击一次才能知道这张牌是干什么的。对新玩家来说，每张牌都要点一下，决策成本很高。
- **建议**：
  - 桌面端：鼠标 **hover 手牌即弹出大图预览**，点击直接进入"打出/选目标"流程（炉石模式）；
  - 至少在法术牌牌面上用 1 行小字显示效果摘要（如"伤害 6"、"抽 2 张"）。

### 🔴 3. 没有战斗日志，关键信息一闪而过（已修改）
`lastLog` 和 `hint` 共用中线一行小字（648-650 行），且 hint 会覆盖 log、1.8 秒后消失。**疲劳伤害、烧牌**这类重要事件（71-86 行）只在这一行出现一次，玩家很容易完全没注意到自己为什么掉血。
- **建议**：
  - 增加一个可展开的**战斗日志面板**（保留最近 N 条记录）；
  - 烧牌/疲劳这类罕见且重要的事件，用居中浮动提示或专门动画强调（例如烧掉的牌短暂展示后燃烧消失）。

### 🟡 4. "已攻击"和"晕眩(刚上场)"状态无法区分
两种状态的随从外观完全一样（都是没有绿色光圈）。💤 图标只对己方晕眩随从显示（522 行），攻击过的随从没有任何标记。
- **建议**：已攻击的随从加灰度/降低饱和度（炉石的"疲惫"表现），并区别于晕眩的 💤。

### 🟡 5. 敌方嘲讽不够醒目
嘲讽只靠 3px 灰边框 + 卡顶一个 11px 的小 🛡️（513、520 行）。当玩家试图攻击英雄被拒绝时，才通过 hint 知道有嘲讽。
- **建议**：选中攻击者后，将**合法目标高亮**（现在已有 pulseR 红色脉冲），同时把**非法目标明显压暗**，让"只能打嘲讽"一目了然；嘲讽随从可以加一个更大的盾形边框或底座。

### 🟡 6. 法术目标与攻击目标的高亮无法区分
两者都用同一个红色脉冲 `pulseR`（515 行）。指向性治疗/增益指向己方单位时也是红色脉冲，语义上是"攻击色"，容易让玩家迟疑。
- **建议**：按意图区分颜色——攻击/伤害用红色，治疗用绿色，增益用金色。

## 二、操作与交互流程

### 🔴 7. 缺少"点击-点击"之间的视觉连接（瞄准指示）
选中攻击者或指向性法术后，没有任何从源头到光标/目标的指示（箭头、连线）。当前只靠 hint 文字"点击敌方随从或英雄发起攻击"。
- **建议**：实现一个简单的 SVG 瞄准箭头（从选中单位指向鼠标位置），或者至少给选中的攻击者一个持续的"待命"动画。移动端可改用拖拽手势：按住己方随从拖到目标上松手。

### 🔴 8. AI 回合不可跳过、节奏固定
AI 回合用固定 750ms 间隔回放快照（453 行），出牌多时一回合要等好几秒，且玩家在等待期间**点击自己的手牌没有任何反应**（`handleHand` 第一行就 `if (!myTurn) return`，370 行）。
- **建议**：
  - AI 回合允许玩家点击手牌**查看**（只读，不可打出）；
  - 增加"加速/跳过动画"按钮或点击屏幕加速；
  - 设置项里提供动画速度选项。

### 🟡 9. "结束回合"按钮缺少状态提示
当还有可用法力 + 可出的牌，或还有能攻击的随从时，按钮外观与"无事可做"时完全一样（652-657 行）。新手很容易漏掉行动就结束回合。
- **建议**：无事可做时按钮变成醒目的绿色/发光（"可以结束了"），仍有可行动项时保持普通样式，并可在按钮上加小红点或提示数字。

### 🟡 10. 取消选中的方式没有引导
点击战场空白处可以取消选中（640 行 onClick），但界面从未告诉玩家这一点；点同一张手牌反而是"打出"而非"取消"，与很多玩家直觉相反。
- **建议**：选中状态下显示一个明确的"✕ 取消"小按钮，或在 hint 中补一句"点击空白处取消"。高费打不出的牌，第二次点击应提示而不是无声失败（目前已有 hint，这点做得不错）。

### 🟢 11. 没有投降/认输入口
劣势局玩家只能等死或刷新页面。对局中也看不到规则说明（规则只在主菜单，605-614 行）。
- **建议**：对局界面加一个菜单按钮（⚙️），内含"认输""规则说明""返回主菜单"。

## 三、动画与反馈

### 🔴 12. 攻击/出牌/死亡没有过程动画
- 攻击：只有飘字伤害数字，攻击方没有任何移动或冲撞动画，AI 回合尤其难看清"是谁打了谁"。
- 出牌：卡从手牌瞬移到场上。
- 死亡：随从在 `dmgMinion` 里直接被 filter 掉（69 行），瞬间消失。

**建议**（按性价比排序）：
1. 攻击时给攻击方一个快速"前顶"位移动画（transform 200ms），AI 攻击尤其需要；
2. 随从死亡先播放 300ms 的淡出/碎裂动画再移除（可以先标记 `dying` 再延迟删除）；
3. 出牌时从手牌位置飞到场上位置（FLIP 动画）。

### 🟡 13. 多段伤害飘字会重叠
所有飘字都定位在 `left:50%, top:-4`（474 行），同一目标连续受到两次伤害时数字完全重叠。
- **建议**：按同一 key 上的序号给飘字加水平/垂直偏移，或排队依次播放。

### 🟡 14. ⚠️ 内嵌组件导致 CSS transition 失效（代码问题，但直接影响体验）（已修改）
`MinionEl`、`HandCard`、`HeroEl`、`Badge` 都定义在 `ArcaneThrone` 组件**内部**（496-583 行）。每次 render 都会创建新的组件类型，React 会**卸载并重新挂载**整个子树——这意味着手牌选中时的 `transition: transform .15s`（558 行）实际上不会产生动画（元素是重新挂载的），未来加任何 CSS 过渡动画也都会失效，且白白损失性能。
- **建议**：把这些子组件移到模块顶层，通过 props 传入所需状态/回调。这是后续所有动画优化的前提。

### 🟢 15. 缺少音效
出牌、攻击、受伤、胜负都没有声音反馈。即使只加 4-5 个基础音效（Web Audio 合成即可，无需素材），打击感也会明显提升。记得提供静音开关。

## 四、布局与适配

### 🟡 16. 选中卡牌预览可能遮挡我方战场
预览面板固定 `bottom:138`（667 行），在矮屏幕（横屏手机）上会盖住我方随从区，而此时玩家可能正要选择己方随从作为增益目标。
- **建议**：预览面板改为靠屏幕左/右侧显示，或在进入"选目标"状态后自动缩小/半透明。

### 🟡 17. 字号普遍过小
大量 9-11px 的文字（手牌名 9px、牌库计数 10px、log 11px）。在手机上低于 12px 的中文可读性很差，也低于无障碍建议的最小值。
- **建议**：正文类信息至少 12px；手牌名可以在 hover/选中预览里看全名，牌面上允许截断。

### 🟢 18. 随从区横向滚动没有指示
6 个随从 + 间距超过窄屏宽度时依赖 `overflowX: auto`（641 行），但没有滚动提示，玩家可能不知道屏幕外还有随从。
- **建议**：窄屏时缩小随从卡尺寸保证 6 个全部可见（用 `clamp()` 同手牌的做法），避免滚动。

## 五、无障碍（Accessibility）

### 🟡 19. 完全不可键盘操作、无语义
所有可点击元素都是 `div` + `onClick`，没有 `button` 语义、没有 focus 样式、没有 aria 标签。
- **建议**：交互元素换成 `<button>` 或加 `role="button"` + `tabIndex` + 回车触发；至少保证 Tab 能遍历手牌和随从。

### 🟢 20. 颜色依赖问题
- 攻击力/生命值徽章用金/红区分（523-524 行），色弱玩家难以分辨——建议附加 ⚔️/❤️ 图标或固定左右位置心智（目前左攻右血是固定的，这点好，可以在规则页明确说明）。
- 受伤(亮红)与满血(暗红)的生命值底色差异太小（524 行）。
- 全部依赖系统 emoji 渲染，不同平台观感差异大；长期可换成统一图标集。

## 六、对局体验（超出纯 UI，但影响整体感受）

| 优先级 | 建议 | 说明 |
|---|---|---|
| 🟡 | 起手换牌（调度/Mulligan） | 当前开局直接发 3 张（316 行），起手卡费用全高时挫败感强 |
| 🟡 | 胜负结算更有仪式感 | 当前 900ms 后直接弹遮罩（352-357 行），建议先播放英雄死亡动画 |
| 🟢 | 回合计时不存在，但也没有"思考中"反馈 | AI"思考"是瞬时计算+回放，可加 0.5s 的"对手思考中…"过场让节奏更自然 |
| 🟢 | 套牌可视化 | 牌库纯随机（buildDeck），玩家无法预期；长期可加简单的卡组预览或构筑 |
| 🟢 | 对局统计 | 结算页只显示回合数，可加造成伤害、击杀随从数等小结 |

---

## 建议的实施顺序

1. **先做第 14 条**（子组件移出主组件）——这是所有动画类改进的前提，半小时内可完成。
2. **第一批（核心体验）**：敌方随从详情查看（1）、法术牌效果可见（2）、攻击动画 + 死亡动画（12）、AI 回合可加速（8）。
3. **第二批（顺手感）**：瞄准箭头（7）、结束回合按钮状态（9）、战斗日志（3）、目标高亮区分（5、6）。
4. **第三批**：音效、布局适配、无障碍、起手换牌。
